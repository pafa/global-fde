# 阅读索引：先作哪项判断，再去哪里找证据

第一次来，可以按眼前需要选一个入口：

- **从头理解这个概念：**从[序章](../chapters/C00.md)开始，随后按全书目录阅读。
- **按自己的角色选读：**先看[序章中的三类读者路线](../chapters/C00.md#三种读者可以从不同地方开始)。

目录按阅读顺序连续编号。可按七篇顺读，也可直接查找行业、国家或当前任务。

## 容易卡住的词，先这样理解

下表解释本书讨论中的用法，不代替具体供应商的产品文档。遇到同一个词在不同项目中含义不同时，以该章写明的对象与条件为准。

| 词语 | 普通语言解释 | 继续读 |
| --- | --- | --- |
| FDE | 前线部署工程师。贴近客户实际工作并承担工程交付；不同公司的职责和产品反馈安排并不相同。 | [序章](../chapters/C00.md)、[责任边界](../chapters/C32.md) |
| Agent | 能调用软件工具、推进任务的 AI 程序。能生成答案与有权执行动作，需要分别判断。 | [模型与工程变化](../chapters/C04.md)、[可靠运行](../chapters/C07.md) |
| Deployment Strategist | 部署策略岗位。相关 Palantir 材料里涉及问题发现与工作安排；不要据英文名称推定所有公司的职责相同。 | [Palantir的现场与产品](../chapters/C02.md) |
| 基线 | 改变之前或用于比较的工作方式及其表现。没有比较对象，很难知道改善了哪一步。 | [问题发现](../chapters/C05.md) |
| 业务语义 | 一个字段或状态在工作中究竟表示什么。两个系统都写“库存”，可能并未计算同一种数量。 | [数据含义](../chapters/C06.md) |
| 本体／Ontology | 用对象、它们的关系和相关动作表达业务的一种方式。本书不把产品术语直接等同全部哲学或计算机学科用法。 | [数据含义](../chapters/C06.md) |
| API／接口 | 程序之间交换信息或请求动作的约定入口。调用成功，还要继续确认业务是否真正完成。 | [可靠运行](../chapters/C07.md) |
| 提示注入 | 外部网页、文件或工具结果夹带指令，诱导AI越过原任务和权限；资料内容不会自动成为用户授权。 | [运行边界](../chapters/C07.md)、[配套测试](../chapters/C08.md) |
| AI FDE／Evolve | 厂商用来描述辅助构建或迭代系统的产品；具体可改对象、验证与批准方式须分别检查，不代表无人负责整段交付。 | [Palantir的产品机制](../chapters/C60.md)、[跨公司交付比较](../chapters/C59.md)、[岗位与工具变化](../chapters/C30.md) |
| MCP | Agent 寻找、调用外部工具的一套连接约定。连得上工具，不表示已获得完成任意业务的权限。 | [模型与工程变化](../chapters/C04.md) |
| 工具调用 | AI 程序请求另一个软件功能执行某件事；请求、实际执行和结果回传是不同环节。 | [可靠运行](../chapters/C07.md) |
| 原生音频 | 在所讨论的系统中直接处理或生成音频的能力。具体支持什么、如何接入，以该章所引产品资料为准。 | [可靠运行](../chapters/C07.md) |
| Live API | 运行章节所述实时交互接口。它是具体产品的名称，不是对所有实时系统的统称。 | [可靠运行](../chapters/C07.md) |
| 评估／Evals | 用一组任务与判断规则检查系统表现。总分之外，还要看错误会影响谁、发生在哪类任务。 | [上线评估](../chapters/C08.md) |
| 生产环境 | 系统实际承担日常工作、其结果会被使用的环境。与展示、试验环境分开记录。 | [可靠运行](../chapters/C07.md)、[上线评估](../chapters/C08.md) |
| 上线、采用、成效 | 上线是可进入实际运行；采用是有人在使用；成效还要证明工作或结果发生了什么变化。具体范围不能省略。 | [采用与接手](../chapters/C09.md) |
| 连接器 | 帮助一套系统与另一套系统交换数据或动作的软件部件。连接完成后，含义、权限和维护仍需安排。 | [数据含义](../chapters/C06.md)、[团队组成](../chapters/C25.md) |
| 编排 | 给多个动作规定先后、条件和交接。每个动作单独正确，不保证组合起来也正确。 | [金融纠错](../chapters/C12.md)、[Agent带来的变化](../chapters/C30.md) |
| 回滚／恢复 | 变更不符合预期时，恢复到能够继续服务的状态；已经发生的业务后果不一定能随软件一并撤销。 | [上线评估](../chapters/C08.md)、[退出与恢复](../chapters/C28.md) |
| 百分比与百分点 | 从 50% 到 67%，相差 17 个百分点；它不等同于在原来数值上增加 17%。比较时先看分母和测量对象。 | [Agent带来的变化](../chapters/C30.md) |
| 统计显著性 | 按研究采用的统计方法，判断观察到的差异在假设没有真实差异时是否罕见。结果依赖方法、样本与门槛；未达到标准，不等于证明完全没有差别。 | [Agent带来的变化](../chapters/C30.md) |
| 同源材料 | 几份材料可能来自同一项目、数据或发布者。转述次数增加，不等于获得了更多独立验证。 | [序章](../chapters/C00.md)及各章注释 |
| 固定总价与按结果收费 | 前者先约定一项工作的价格，后者把收费与合同定义的结果挂钩；前者不自动等于后者。 | [合同与价格](../chapters/C36.md) |

## 按国家找组织与工作条件

国家篇选择8个重点国家。国家章节不是市场排名，也不把企业总部等同全部项目所在地。下面列的是各章材料能帮助检查的具体问题；章节中的主案例、阶段与限制共同决定判断范围。

| 国家与入口 | 企业或机构怎样组织工作 | 进入现场时重点检查什么 |
| --- | --- | --- |
| [美国](../chapters/C21.md) | 平台供给、共同采购与客户自己的工程安排相互衔接 | 获得工具之后，谁仍需负责资料、权限和运行 |
| [英国](../chapters/C38.md) | 内部数字团队与专业人员共同试验，必要时重选商业产品 | 专业复核能否回到开发，确认之后还能否纠正 |
| [法国](../chapters/C39.md) | 业务机构提出问题，模型伙伴进入既有孵化或集团合作 | 长期合作能否拆成各项业务可验收的改变 |
| [德国](../chapters/C40.md) | 工厂知识、集团平台与工业供应商共同参与 | 设备版本、维护责任及资料对员工的影响 |
| [中国](../chapters/C22.md) | 采购要求、平台伙伴与相似客户工程使用不同名称 | 买的是驻场时间、固定功能，还是允许探索的工程责任 |
| [日本](../chapters/C23.md) | 伙伴先积累内部使用经验，再组织客户支持 | 内部知识怎样变成客户可用、可维护的能力 |
| [印度](../chapters/C42.md) | 服务交付能力与当地语言、社区知识相遇 | 语言评估与具体使用者能否进入项目选择 |
| [新加坡](../chapters/C43.md) | 客户已有内部数字产品团队 | 外部伙伴补什么，怎样接入现有产品维护 |

跨国比较时，可以沿四项相同问题回读：采购怎样进入，现场由谁改动，语言与数据有哪些条件，客户怎样接手。不能拿一国的采购优惠与另一国的试验分类结果比较成熟度。GSA材料主要改变获取条件，Consult显示专业复核如何进入开发，France Travail显示内部需求怎样进入试验；同一个机构也可能同时需要这三类安排。

四个制度与项目窗口还可以用同一组字段对照。表中空白就是下一项研究问题，不能靠采购规模或国家标签补齐。

| 记录单元 | 采购怎样进入 | 现场由谁改动 | 语言与数据条件 | 客户怎样接手 |
| --- | --- | --- | --- | --- |
| GSA 与 OpenAI 协议 | 共同采购渠道与费用条件明确 | 没有公开逐机构的项目改动记录 | 协议不证明具体业务资料已经接通或各种语言已测试 | 有培训支持，未据此确认各机构能独立维护应用 |
| Consult 苏格兰试验 | 所引材料为内部试验评估，非完整采购合同 | i.AI 工程人员与专业复核者协作；主题锁定造成修订困难 | 特定咨询反馈与主题表；换议题后的可比性需重查 | 政府内部团队建设；长期运行与复核资源仍需安排 |
| France Travail 的应用与孵化 | 既有应用、公开合作与后续扩展分阶段 | 员工提出困难，内部试验，供应商提供技术 | 本机构服务数据与专业术语；未取得跨语言效果比较 | 有内部孵化机制，未取得逐应用维护人力和成本 |
| Redbox 后续开发决定 | 已有内部工具与商业替代品重新比较 | 政府决定停止继续开发，并转移工程经验 | 公告涉及文档工作，未公开逐项等价测试 | 后续知识保留；不把停止开发写成所有应用已迁移完成 |

其他地区的交付案例可读[工作条件不同，交付怎样调整](../chapters/C24.md)。Pair的内部产品、ENERGYai的合同与部署、Nubank的支付入口不构成发展阶段排名。Jacaranda在肯尼亚的语音试点，与Ona为该机构做的跨国数据合作也须分开：后者的首个报表国家未具名，不能因机构所在地相同而补成肯尼亚部署。
