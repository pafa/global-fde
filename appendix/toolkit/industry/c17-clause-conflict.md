# 两项修改碰到同一句：冲突与裁决

工具编号 TK-C17-01。对应[第十七章](../../../chapters/C17.md)。条款、规则和裁决完全虚构，仅演示文档工程，不判断真实合同法律效力。

## 怎么用

固定同一原稿和条款位置，为每项修改保存规则ID与理由。程序先发现文字重叠，负责律师判断规则关系，客户授权人决定尚未获准的例外。没有授权决定时保留待决状态，不为了交付一份干净文稿而猜选。

## 已填例子

原文 V1第3条：“乙方向甲方发送月度服务报告，收件人为附件A所列联系人。”

| 项目 | 记录 |
| --- | --- |
| R1 | 报告只发给甲方书面确认的联系人 |
| R1改稿 | 乙方仅向经甲方书面确认的附件A联系人发送月度服务报告。 |
| R2 | 集团内部项目联系人可接收报告，无须逐次确认 |
| R2改稿 | 乙方也可向甲方集团内部项目联系人发送，无须逐次确认。 |
| 冲突C1 | R2修改可能允许附件A外未确认人员接收；逐次发送批准和首次名单确认被混在一起 |
| 授权D1 | 教学客户负责人确认：新增联系人先书面加入获批名单，以后发送不再逐次批准 |
| 合并V2 | 乙方向附件A所列联系人发送月度服务报告；新增甲方集团内项目联系人须先由甲方书面确认加入附件A，此后发送无须逐次确认。 |
| 复核 | 负责律师核对V2符合本次D1；文件人员确认正文和附件仍对应 |

若D1缺失：保留V1、R1/R2建议和C1，状态“待客户确认名单规则”；V2只是候选，不能标为已接受。以上是互斥分支，不是同一事项同时获批与待批。
