# 一条建议何时失效

工具编号 TK-C18-01。对应[第十八章](../../../chapters/C18.md)。时间、对象和版本均为虚构教学；不含任何真实设备参数或网络操作指令。下载[已填时间线CSV](c18-stale-advice-example.csv)。

## 怎么用

给建议保存对象、输入版本、适用前提和生成时点。执行前比较当前前提，前提变动优先于尚未超时的有效期。拒绝旧建议后写清谁接手，不能只留下程序报错。

## 已填时间线

| 时刻 | 事件 | 状态与责任 |
| --- | --- | --- |
| 14:00 | 对S-7读取v41，开始生成A-9 | 分析任务保存输入版本 |
| 14:02 | 既定维护开始，运行记录变为v42 | 维护负责人确认生效；原前提不再成立 |
| 14:03 | A-9返回，依据仍为v41 | 执行前校验拒绝，不发送设备变化请求 |
| 14:04 | 值班负责人确认继续既有维护，退回分析 | A-9标失效；不是设备动作执行失败 |
| 14:10 | 新分析读取当前资料 | 重新检查权限与前提；不能自动恢复A-9 |

结论：失效点是14:02的状态改变，14:03只是发现失效。即使A-9设有五分钟时限，也不能覆盖状态改变。
