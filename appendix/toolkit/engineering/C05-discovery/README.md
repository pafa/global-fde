# C05：一页项目约定

本包使用合成维修情境，没有真实客户、真实访谈或实际试用结果。[已填约定](agreement-filled.json)把观察、解释、三条路线和暂停条件分开；[20项回放输入](replay-cases.csv)已填预期，actual_observation 保留 not_run，不冒充已经测试的软件。这20条仅是三种条件按12、6、2条重复的分流演示，不是20种边界覆盖。

使用顺序：先只读三条观察，自己选表单、AI提取或自动预约；再看选择理由；最后用回放表检查你设计的分流。普通项应由员工确认，模糊项转人工，须拆机项退出自助；不能把所有项都交给同一个“完成”按钮。

示范答案是先改说明。另一条合理路线是，在新证据表明用户已提交型号而员工查找耗时很高时，试做资料提取；那会改变原问题，须记录新证据，不能偷偷把功能加进原约定。正式试用人数、持续时间和容忍变化尚待客户按工作量与后果确定，此包没有替所有企业设门槛。

需要复用时填[空白约定](agreement-blank.csv)。主管确认范围和人工接续，维修代表确认信息够用，技术人员确认资料可读与实现边界。只由工程师签满所有格子不构成这项合作。
