# 结语　把能力留在问题发生的地方

一家医院连接了数据，仍然需要有人确认出院安排。北蒂斯和哈特尔普尔信托在质量报告中写下的两名协调人员，在[C11 医疗](C11.md)里提醒过我们：看得见任务，与任务有人完成，是不同的事情。[^1]

读到这里，我们已经能把这个差别看得更细。人员还在，不说明自动化毫无作用；软件已经上线，也不说明人的工作已经得到妥善安排。要知道改变的价值，必须沿着具体工作继续走：重复劳动少了多少，等待发生在哪里，新的信息由谁维护，下一位接手者能否理解。

这是一本讨论 FDE 的书，也希望帮助读者形成一种不必依赖这个名称的判断力。当下次有人展示一个新系统、提出一个合作方案，或者邀请你担任某个新岗位时，你能够先问清它准备改变什么，再判断这份投入是否值得。

## 回到最初的名称

追溯 FDE，很难用一个生日解释所有事情。名称留下记录、相似工作早已存在、公司形成一种组织方式，是几条相互关联又不重合的历史。把它们分开，不会削弱这个概念，反而使我们知道它究竟增加了什么。

这本书最关注的增加，是让理解问题的人有机会修改系统，让修改系统的人持续面对实际使用，再让现场所得改变后续产品。每一个连接都可以单独存在；当它们能够较短距离地往返时，客户的问题才不必总在需求文件、工程排期和支持工单之间反复被重新解释。

但缩短距离要花成本。工程师进入现场，需要时间理解业务；客户参与开发，需要暂时离开原来的工作；平台接收反馈，需要判断哪些属于共同产品，哪些只是一个客户的特殊选择。距离变短，未必意味着总投入自然减少。它是否值得，应当由被解决的问题和留下的能力证明。

所以，不必先争论某支团队是不是“正宗 FDE”。更有用的判断是：它能否找到妨碍工作的具体条件，是否有权作必要的工程改动，能否把改动放进真实使用中检查，又是否有人承接之后的变化。名称帮助我们寻找这种安排，不能替代对安排本身的检查。

## 回到维修企业，完成一项有条件的决定

现在回到序章那家教学维修企业。它与前面提到的真实医院没有项目联系。我们仍没有给它编造上线成果，而是把读者在一次项目讨论中可以作出的判断写完整。

假定团队补查了三项输入：选定设备的维修说明已经齐全；工单记录尚不能把“等人判断”和“等备件”稳定分开；现有搜索功能能找到文件，但员工仍需要反复翻页定位。练习另设两周试用期。以上都属于教学设定，尚不足以证明客户总等待会减少，却已允许作出一项范围较小的决定。

**示范决定：先改善一类请求的资料查找，不批准全网点自动排维修；由内部服务负责人带领一个小范围试用，暂不购买长期 FDE 驻场。** 这是选择建设顺序，并不是否定后续共同工程的可能。

| 决定记录 | 这一次怎样填写 |
| --- | --- |
| 已知输入 | 所选设备资料齐全；员工查找步骤繁琐；等待原因尚未可靠分类 |
| 待验证假设 | 带出处的检索建议能减少翻查，不增加员工核对负担 |
| 首先改变什么 | 保留工单处理与排班方式，只在员工查资料时给出可回查的段落 |
| 暂不做什么，以及为什么 | 不自动承诺维修时间；库存和排班状态尚未可靠接通 |
| 可比较的替代方案 | 先整理现有搜索和目录；若同样减少翻查，就采用更简单的办法 |
| 观察什么 | 同类请求的查找、核对和补问耗时；员工实际采用；错误建议在哪里被发现。总等待另行记录，不与查找时间相混 |
| 谁作判断 | 服务负责人确认这类请求是否值得改善；技术负责人验证资料与出处；一线员工报告实际使用中的额外步骤 |
| 代价怎样记 | 采购、整理资料、员工核验、运行和后续维护分别记工时或报价；未取得报价的项目留待查，不填一个好看的回报率 |
| 下一次决定 | 两周结束，由服务负责人召集技术负责人和一线员工复查上述记录；若请求太少或异常未覆盖，先补样、不扩围。若简单搜索足够，停止扩大开发；若仍有权限、状态或产品接口缺口，再比较是否需要共同工程团队 |

这张表有一个允许被推翻的主张：目前最值得测试的是资料查找，而不是自动排班。假如补查发现最长的等待来自备件未到，团队就应把总等待目标转向库存与调度问题；资料助手仍可能节约员工时间，却不应继续占用“减少客户总等待”的预算名义。

另一种合理选择是暂不建设新工具，先改进工单记录。它会推迟演示变成产品，却能减少把资源投入错误环节的风险。两种选择的差别不在于谁更相信 AI，而在于现有输入是否已经足够支持一个有用、可比较的小改动。

如果试用后真的需要 FDE，委托也可以更准确：不是笼统地要求外部团队“让 AI 落地”，而是让其与客户一起处理某个现有团队无法完成的接口、性能或产品缺口。客户仍要确定工作目标，供应商需要拥有相应的工程权限，双方再用同一类请求检查改变是否进入实际使用。[C07 可靠运行](C07.md)的运行轨迹、[C08 上线评估](C08.md)的评估和[C26 项目经济性](C26.md)的账本，分别帮助把执行、证据和投入接起来。

下一位负责人接手时，应当能读懂为什么没有批准自动排班，也能知道什么新证据会使这个决定改变。这比留下一串“要注意权限、维护和责任”的口号更有用：决定带着条件留下，组织才有办法继续改变它。

换成自己的工作，可以先填这份空白记录：要改变的工作是____；目前依据是____，仍缺____；我先选择____，暂缓____；由____对____负责；在____时检查____，若发现____就重做决定。填不下的空白，往往就是下一次会议需要取得的输入，不必先把它包装成一份完整方案。

## 不同岗位，要带走不同的责任

企业负责人需要带走的，是对选择的责任。哪些问题值得共同探索，哪些能力应当掌握在内部，谁能决定工作方式改变，多少持续投入可以接受。技术团队可以提供判断材料，无法替经营者决定所有取舍。

产品与技术负责人需要带走的，是对连接处的耐心。一个模型回答、一项系统动作、一条业务记录和一次用户理解，未必同步完成。把它们接起来，需要解释，也需要实际改动。现场反馈只有进入产品的比较与排期，才有机会减少下一次交付的重复劳动；同样，并非每次客户请求都值得变成共同功能。

准备进入这个领域的人，需要带走的是一种可练习的工作尺度。先把一个适当范围的问题追清、做通、验证并交给别人接手，再扩大责任。能够准确说出自己已经验证什么、还需要谁判断，和能够快速生成方案一样重要。复杂工作不要求一个人什么都懂，它要求一个人知道何时必须找到另一种专业。

三类读者的责任在这里相遇。经营者提供可成立的目标与组织条件，技术负责人让改变能够运行，实践者把具体问题追到有依据的下一步。任何一方完全缺席，其他人都可能用额外劳动暂时遮住空缺，却很难一直遮住。

## 全球比较，最终要回到本地问题

跨行业、跨地区阅读的价值，不只是多认识几家公司。更有用的是辨认一种经验依赖哪些条件，然后检查这些条件能否在自己的环境里成立。

同样是资料助手，教师关心学生是否形成理解，核保人员关心材料是否属于这一次申请，客服人员关心建议能否进入有效办理。一个共同的语言模型，可以帮助处理这些工作，却不能替它们规定同一套完成标准。

地区比较也如此。一地的采购安排可能帮助取得软件，另一地的内部团队可能已经能完成大部分改造，本地伙伴则可能承担语言、行业或系统连接。复制之前，要查清这些工作由谁提供，而不是只复制可见的界面和岗位名称。

跨地区阅读也会改变决定。某地能够买到一项服务，不表示能改变其中的模型；能取得本地语言材料，也不表示少数语言使用者已经被充分测试。地区篇反复使用采购进入、现场改动、语言与数据、客户接手四个问题，就是为了把这些差异落到一次合作的安排上，而不是替国家排名。

资料更新后，决定应当允许重做。一次需要密集共同工程的任务，后来可能成为成熟功能；原本可以标准化的工作，也可能因新的权限或使用人群再次需要探索。经验有时间和条件，保存它们比保存一个永远正确的结论更重要。

## 留下什么，才算向前走了一步

一个项目结束时，可以留下许多东西：代码、合同、培训材料、使用数字、一次成功的演示。它们各有作用，但还可以再看一层：这个组织现在能够做哪些以前做不到的事，能否理解正在发生的事，以及条件改变时有没有办法调整。

能力留在现场，不等于供应商必须离开，也不等于客户必须自己开发全部软件。长期合作可以很有价值，前提是双方知道各自承担什么，客户能够作出知情选择，关键工作不会只藏在某一个人的记忆里。外部支持越专业，客户也越需要具备提出问题、检查结果和安排下一步的能力。

回到北蒂斯报告中的协调人员。他们不是本书需要消除的例外，而是提醒我们观察技术所进入的工作。一项状态如何变得可信，一个安排如何被另一方接住，一次变化如何让下一班人员知道，最终都要落实为有人能够完成的动作。

FDE 可能继续成为重要职称，也可能分化为别的岗位和组织形式。读者不必替这个名称保证未来。更值得保留的，是走近问题的意愿、作出实际改动的能力，以及让改动接受检验的习惯。

序章的问题现在可以得到一个更具体的回答。工程师是否需要走进来，取决于哪段工作还不能被清楚解释和可靠改变；投入多少，取决于这段缺口的价值与可替代办法；留下什么，则要看下一位负责人能否依据记录继续作决定。

下一次面对一场漂亮演示，可以先请团队填出那张决定记录。从一件普通工作开始，沿着输入、改变与后果走一遍。走到那里，FDE 才从一个值得讨论的名称，成为一种可以选择、也可以拒绝的实际安排。
